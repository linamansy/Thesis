5a. **Chapter 3, validity rule (decided 18 Oct 2026, before the real runs, the same for C1/C2/C3).** State the fixed model: qwen3:8b, Ollama digest `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`. Then describe validity in three parts:
   - **valid** (main metric): the file passes our strict validator (well-formed XML, BPMN definitions, at least one process, start and end event, unique ids, every sequence flow points to an existing element).
   - **bpmnlint_valid**: BPMNGen's own bpmnlint verdict, reported next to it. It is more lenient: in the smoke test it accepted a file whose diagram section used an undeclared `bpmndi:` namespace.
   - **di_stripped**: if a file is not valid only because of its diagram section (`<bpmndi:BPMNDiagram>`, which holds drawing positions and no process meaning), that section is removed and the structural metrics (precision, recall, F1, behavioral similarity) are computed on the process part. The file still counts as not valid. Nothing else is repaired: a typo in the process part (smoke test: `b3pmn:sequenceFlow`) is not rescued and scores 0.
   Why: the strict rule keeps validity comparable and honest, and the rescue stops a pure drawing error from hiding a correct process. Report per condition how many files were valid, bpmnlint-valid and di-stripped. In the smoke test both XML errors were already in qwen3's raw answer, so they are model errors, not caused by BPMNGen's cleanup.
   Suggested sentence (validity): *"Syntactic validity was assessed with a strict XML/BPMN validator. For the structural metrics only, a model whose sole defect lay in its diagram-interchange (BPMNDI) section was evaluated without that section; such models remain counted as invalid and are reported separately (di_stripped). BPMNGen's own bpmnlint verdict is reported alongside for comparison."*

5c. **Chapter 3, Ollama server settings.** All runs used two Ollama server settings: `OLLAMA_FLASH_ATTENTION=1` (a faster attention computation that needs less GPU memory) and `OLLAMA_KV_CACHE_TYPE=q8_0` (the model's context memory stored with 8 bits instead of 16).    Suggested sentence: *"Ollama was run with flash attention enabled and an 8-bit (q8_0) key–value cache, so that qwen3:8b with BPMNGen's fixed context window of 16,384 tokens fitted entirely in GPU memory. These server settings were identical for all conditions and repetitions."*
5d. **Chapter 3, Ollama version and guard.** Name the Ollama version: **0.40.6**. Ollama updates itself, so every run records the version, the model digest and the server settings in its run_info.json, and a run (or a resumed part of a run) does not start if any of them differs.
   Suggested sentence: *"All generations used Ollama 0.40.6 with the qwen3:8b model file identified by its digest (500a1f06…b8b41); the version, digest and server settings were recorded for every run, and a run could not continue if any of them changed."*

5f. **Chapter 3, trace threshold.** The knowledge-traceable diagnostic (extra tasks that look like they came from the knowledge block) uses a fixed threshold of **0.5**, decided on 18 Oct 2026 before the real runs. A sensitivity check at 0.4, 0.5 and 0.6 is reported next to it. State that the value was fixed before seeing any results, so it can't look chosen afterwards.
   Suggested sentence: *"An extra task was counted as knowledge-traceable if its label had a cosine similarity of at least 0.5 to a sentence of the knowledge block and was more similar to that sentence than to any sentence of the description. The threshold was fixed before the experiment runs; results at 0.4 and 0.6 are reported as a sensitivity check."*
5g. **Chapter 3, thinking switched off with Ollama's own parameter; discarded first run; failed-generation rules.**
   - What happened: BPMNGen asks for no thinking only by writing "/no_think" in the prompt. With Ollama 0.40.6, qwen3 thought anyway and Ollama returned that thinking in a separate field that BPMNGen never reads. So the thinking was hidden and not saved, and in one case (case 21) it went into a loop of 122,236 tokens. A replay of one recorded request showed 11,928 characters of hidden thinking next to 2,403 characters of BPMN.
   - The fix: the harness adds Ollama's own switch `think: false` to BPMNGen's request. This is the only change to BPMNGen's request, and it makes Ollama do what BPMNGen already asks for. No BPMNGen file was changed.
   - Any thinking that still appears is saved and flagged, never repaired: text in the thinking field, or a `<think>`/`</think>` tag in the answer (qwen3 occasionally writes a draft followed by `</think>`).
   - Discarded run: the first, partial repetition 1 (9 C1 cases made with hidden thinking) was kept but discarded, and repetition 1 was restarted from scratch with the fix. Say this openly; it was decided before any evaluation.
   - Failed generations: an answer that passes the context window (the harness stops it) and a generation that exceeds 900 s (the process is killed) both count as failed generations. They are scored as 0 and never retried, because retrying until the model succeeds would favour it. Only a technical Ollama outage stops the run so the case can be resumed.
   Suggested sentence: *"BPMNGen requests non-thinking output through a prompt tag; because the Ollama version used did not honour this tag for qwen3, Ollama's own thinking switch was disabled in the generation request, which matches BPMNGen's intended behaviour. A first partial run made before this correction was discarded. Generations that exceeded the context window or the time limit of 900 s were recorded as failed and scored as zero; they were not repeated."*
5h. **Chapter 3, stray `</think>` and failure types (decided 18 Oct 2026, before the real runs).** Even with thinking switched off, qwen3 sometimes stops in the middle of the XML, writes `</think>` and continues (2 of 6 smoke-test generations). BPMNGen's cleanup removes only complete `<think>…</think>` pairs, so the file stays invalid. This is treated as a genuine model failure: it is not repaired, not retried, and BPMNGen is called no differently. The model scores 0 and the case is flagged (thinking_detected). Every failed or rescued case is given exactly one failure type, reported per condition: time-out, context limit, thinking detected, missing namespace (rescued for the structural metrics), other invalid XML.
   Suggested sentence: *"Occasionally the model emitted a stray closing think tag inside its BPMN output despite disabled thinking. Such outputs were treated as genuine generation failures: they were neither repaired nor regenerated and were scored as zero. For each condition we report the number of failures by type (time-out, context limit, thinking artefact, missing BPMNDI namespace, other invalid XML)."*
